# АСМ · ИИ-планирование маршрутов

MVP по ТЗ «ИИ-ускорение логистики: распределение заявок» и плану разработки.

## Запуск
```
python -m pip install -r requirements.txt
copy .env.example .env        # вписать OPENAI_API_KEY
python -m uvicorn app:app     # http://localhost:8000
```
Без ключа система тоже работает: заявки разбираются простыми правилами, а чат-помощник выключен.

## Что умеет
1. **Загрузка заявок**: JSON (формат выгрузки 1С, см. `data/sample_tasks.json`), CSV, Excel. Кнопка «Пример заявок» загружает тестовый набор.
2. **ИИ-разбор (OpenAI Responses API)**: из карточки КА выбирает складской адрес вместо юридического; из текста «забрать масло к 9.00 → выгрузить в Балашихе» делает две связанные точки; понимает «по согласованию», «грузим 2 машины», «до 11 часов»; оценивает вес; выделяет «требует проверки» и задаёт вопросы логисту.
3. **Маршрутизация (OR-Tools)**: учитывает окна, грузоподъёмность и объём, закрытый кузов, европаллету (не входит в Staria), допуск водителей к машинам, графики 5/2 и 2/2, резервную ГАЗель (берётся в последнюю очередь), срочные заявки, пары «забрать → отвезти», выезд с базы в 08:00.
4. **Рабочее место логиста**: карта, перетаскивание точек между водителями, снятие с плана, правка окон и адресов, выбор другого склада контрагента из списка, отметка «машина недоступна» и «водитель вышел / не вышел» на дату (например, выход в субботу), пробег на начало дня, пересчёт с сохранением ручных правок, срочная заявка после расчёта, чат «Балашиху отдай Ушакову». По умолчанию открывается следующий рабочий день.
5. **Вторая проверка порядка: задача коммивояжёра (TSP)**. Для каждого маршрута точным перебором (алгоритм Хелда–Карпа, до 13 точек; больше — OR-Tools) ищется лучший порядок с учётом окон и правила «погрузка раньше выгрузки». После автоматического расчёта улучшение применяется сразу. После ручной правки порядок логиста не трогается: показывается «TSP: другой порядок быстрее на N мин» и кнопка «Оптимальный порядок».
6. **Проверки**: после каждой правки план заново проверяется на перегруз, допуск, окна и конец смены. Нарушения видны до утверждения. Ответ модели проверяется кодом: неверное время, координаты вне Москвы/МО, выдуманные или пропущенные заявки не ломают расчёт, а помечаются «проверить». Утверждённый план нельзя затереть повторной загрузкой (ни из интерфейса, ни из 1С).
7. **Утверждение**: план фиксируется, у каждого водителя появляется лист маршрута `/driver/<дата>/<водитель>` в привычном формате, со ссылкой на Яндекс.Карты и печатью в PDF.
8. **Журнал** (`/api/plan/<дата>/journal`): исходные заявки, результат ИИ, план, все правки. По нему видно, сколько логист переделывает.

## После MVP
- 1С: обработка «Сформировать маршрут» отправляет оплаченные заказы на `POST /api/import/1c/{дата}` (заголовок `X-Token`).
- Bitrix24: `logistics/bitrix.py` отправляет водителю сообщение через `im.message.add`. Нужен вебхук и `bitrix_user_id` водителей.
- Пробки: заменить OSRM на Яндекс Матрицу расстояний (интерфейс `geo.matrix` тот же).

## Тесты
`python -m pytest -q`: 18 сценариев из плана (§10), 3 теста контракта с Responses API, 16 тестов TSP (точный алгоритм сверяется с полным перебором всех перестановок) и 10 тестов API и защиты от плохих данных. Работают без сети и без ключа.
